# Yandex DC 攻撃を自然実験とした日本語 SNS 協調投稿の検証 — 2026-10-13 時点で非現実的と判断

[[nishio]] の問い:「Yandex のデータセンターへのドローン攻撃後に AfD/MAGA アカウントのコメントが急減した、という話がある。日本の SNS における特定の話題がこのタイミング前後で有意に減少したか検証できるか」。対象プラットフォームは X、話題は固有名詞を避けた概念キーワード（排外主義 / 反移民 / 反ウクライナ）。

**結論: 検証の設計自体は可能だが、2026-10-13 時点では実データ取得が壁で非現実的。[[nishio]] 判断で「諦めよう」。** 経緯と、将来再挑戦する時の留保を残す。

## 1. 元の主張自体が未証明（前提を疑う）

- 事件は実在:ウクライナ無人機が Yandex データセンターを連日攻撃（Sasovo 10/8、Kaluga 10/9、Vladimir 10/11, 2026）。技術的なサービス障害は確認済み。
- だが「AfD/MAGA の bot が急減」の“証拠”はバズった traffic グラフで、専門家は **ソーシャル投稿ではなく Yandex の web クローラ（検索ボット）のトラフィックの誤読**と指摘している（RFE/RL, Euromaidan Press, Euronews, Mezha の fact-check 系記事）。独立検証された投稿量の数字は出ていない。
- つまり「troll 網が Yandex インフラに依存していて、落ちたら黙る」という **因果機構そのものが未証明**。日本語圏の該当コンテンツが Yandex インフラに依存している必然性はさらに薄い。[[kouchou-ai]] 的な「ソースは無批判に採用しない」姿勢で言えば、検証以前に premise が弱い。

## 2. 検証対象の切り出し方（方針は妥当）

- 参政党のような固有名詞を名指しせず **概念キーワードで言説総量を測る**:排外主義 / 反移民 / 反ウクライナ。表記ゆれ（漢字・かな・カタカナ・ハッシュタグ、親ロシア/反ゼレンスキー 等）を束ねた lexicon、`lang:ja`、単位は **日次ユニーク著者数**（1 アカウントの連投に頑健）。
- テーマごとに仮説への距離が違うことを明示して測るべき:
  - **反ウクライナ** = Russian info-ops の機構に最も近いが、Yandex 攻撃自体が Ukraine ニュースなので **オーガニック投稿がむしろ増える交絡が最大**。
  - **排外主義 / 反移民** = ドメスティックな論点で、Yandex インフラ依存の事前確率は低い。Oct 8 ちょうどで落ちたら驚きで、強い対照キーワードがないと国内ニュースサイクルと区別できない。
  - 多テーマ総当たりなら **多重比較補正は必須**（偶然の「有意な減少」が必ず出る）。

## 3. 律速は X のデータ取得（ここで断念）

- X API 2026:固定 tier（Basic/Pro）は新規受付終了し従量課金へ移行。read 約 **$0.005/post**、Enterprise 契約なしで月 300 万 read 上限。
- **full-archive search（9 月まで遡って pre/post baseline を作るのに必須）はセルフサーブから外れ、実質 Enterprise**（full-archive/streaming の Enterprise を「月 $42,000〜」とする情報源あり）。
- 誰でも使える安い経路は **recent search = 直近 7 日のみ**。今日（10/13）取れるのは概ね Oct 6–13、つまり **pre が 2 日・post が 5 日**しかなく、まともな baseline が作れない → 日次 volume の有意検定は検出力ゼロ。
- よって X 単体での retrospective な自然実験は割に合わず断念した。

## 4. もしやるなら（将来の再開メモ）

- volume の有意検定は underpowered なので捨て、**account-level の協調クラスタ検定**に振るのが筋:ほぼ同一テキストの多数投稿・投稿時刻の同期・アカウント作成日クラスタ・投稿時間帯の機械的規則性で候補クラスタを先に同定し、同じキーワードを投稿する **オーガニック著者のマッチ対照**（落ちないはず）と Oct 8–11 で沈黙したかを比較。短い窓でも「誰が落ちたか」は見える。
- データ源の代替:**Bluesky / Misskey**（API 開放、母集団は違うが lexicon と協調検出器の dry-run には十分）、または X 履歴を licensed で持つ**ソーシャルリスニング業者**（Brandwatch / Talkwalker / 国内系）。baseline が取れれば CausalImpact（BSTS）や負の二項 GLM（曜日・祝日・トレンド + step 項）を適用できる。これは [[broadlistening]] とは別物の coordinated-behavior 検出タスク。
