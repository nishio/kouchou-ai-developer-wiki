## 位置づけ

2026-11-10 夜の nishio の「新しい可視化の方法を考えて」に AI が案を出し、2026-11-11 の nishio の「all go」で 5 つとも作ったもの。案を机上で並べる前に、[[team-mirai-2025-open-dataset]] の集計（LLM は使わない）で、その見せ方で実際に何かが見えるかを下見した。

- 作ったものは nishio の個人 repo（nishio/broadlistening-visualizations）の作業ツリーにあり、2026-11-11 時点で未 commit・未公開（push は公開と同じなので nishio の指示待ち）。デモの URL はまだ開けない
- 仕組みと確かめた数値の正本は、個人 repo の README の各「〜の作り」節
- 案と見立ては AI のもので、本体に入れるかの判断ではない

## 今のカタログが描いていない 3 つの軸

個人 repo の既存の 5 つ（[[team-mirai-2025-open-dataset]] の「個人 repo のカタログ」）は、どれも「何が言われたか」を読む・寄る・割る見せ方で、次の 3 つは描いていない。

- **いつ届いたか**：元データの PR に作成日時がある（2025-05-15〜07-26）
- **何と一緒に言われたか**：1 つの投稿から複数の意見が抽出される。散布図は「文が似ているか」で置くので、「同じ人が一緒に言ったか」という別の関係は見えない
- **要約から何が落ちたか**：表札と要約は、まとまりの多数派を代表する。似た意見がほとんど無い声は、どの要約にも出てこない

名前は [[post-review-product-direction-2026-10-28]] の「view は手法名ではなく読者の目的の名前で増やす」に合わせた。

## 作った 5 つと、確かめた結果

どれもビルドなしの静的 HTML 1 枚で、入力は `public_result.json`（＋任意の埋め込み）だけ、LLM は使わない。ヘッドレス Chromium（幅 1280px・390px、ライト・ダーク）で肝の操作を動かし、数値は Python で数え直して突き合わせた。

### 話題の流れ（いつ何が届いたか）

意見の日時の属性で日・週に区切り、全体の量と上位のまとまりの積み上げを描く。期間をドラッグで選ぶと、その期間とそれ以外で割合が増えた話題・減った話題を上位・下位のまとまりで並べ、押すとその期間の意見と出典まで降りる。事前計算はしない。

- 量（JST）：最初の 6 日（5/16〜21）で意見 5,510 件（全体の 26%）、6 月は週 400〜750 件、7 月後半は週 4,000〜4,700 件。PR が最も多い日は投票日前日の 7/19
- 公示から投票日前日（7/3〜19）とそれ以外を比べると、上位で割合が増えたのは医療制度・子ども・家族・子育て支援・エネルギー・移民、減ったのは透明性と公正性・地域社会と行政改革・AI の倫理。下位で増えたのは選択的夫婦別姓（2 つ）と同性婚。投票日以降は、デジタル民主主義（選挙制度の DX・インターネット投票など）が増えた
- 話題の顔ぶれは変わっていない（7/1〜19 に初めて意見が届いた下位のまとまりは 400 のうち 2 つ）。動いたのは割合。理由（参加者の層か、マニフェストや聞き手の側か）はこのデータでは分けられない
- **5 月とそれ以降の比べには、1 段目（課題の抽出）の入力の違いが混ざる**。本文が入った入力から抽出されたのは 2025-05 の PR の一部だけで、6・7 月の PR は全件本文なし（[[team-mirai-2025-open-dataset]]）。PR 1 本あたりの意見の数も、5/16〜21 が 4.17 件、6 月 2.30 件、7/1〜19 2.01 件と違う
  - どちらも本文なしの 6 月 → 7/1〜19 でも残る変化：家族 1.4% → 4.3%、子ども 5.6% → 8.5%、移民 1.7% → 2.6%、AI の倫理 7.0% → 5.3%
  - 医療制度（4.8% → 8.9% → 9.8%）は 5 月から 6 月の間に動いており、本文の有無の切り替わりと重なるので、話題の変化とは言い切れない
- 下位のまとまりの短い山（3 日で 5〜13 件）は PR 2〜11 本ぶんで、少数の PR で山ができる。下位は PR の数で比べる

### 要約から落ちた声

同じ投稿の意見を除いて 10 番目に近い意見との近さ（1536 次元の埋め込みの cosine）が、全体の下位 5% の声（1,067 件）を、上位のまとまりごとに並べる。いちばん近い他の投稿の意見と、同じ投稿のほかの意見を添える。重要かどうかは決めず、候補として見せる。

- 並ぶのは 3 種類：要約に出てこない具体的な論点（「千島列島全域の返還を求める方針を明記することは、サンフランシスコ平和条約の条項に相反する可能性がある。」など）、抽出で文脈が落ちた断片（「その日暮らしが現実となっている」）、仕組みそのものへの声（「エンターキーを押すとメッセージが即送信されるため、誤字や機会喪失を招く。」）
- 文脈が落ちた断片は、同じ投稿のほかの意見で読める（1,067 件中 1,014 件は、同じ PR にほかの意見がある）
- まとまりごとの割合は、地域社会の行政改革とインフラ 11.0%・安全保障と情報管理 9.3% が高く、デジタル民主主義 1.0% が低い。表札と食い違う声も見える（「エンターキーを押すと…」は下位「安全保障政策の強化と具体的対策の必要性」に入っている）
- 埋め込みなしで x / y の距離で測ると、埋め込み版との重なりは 12% だけで、測れるのは「配置の上で小さな島にいるか」になる（道は残し、注意書きを出す）
- 時間順の新規性（その時点までに届いた他の PR の意見との近さ）も測ったが、ほぼ同じ声を拾う（低い方から 15 件のうち 14 件が孤立した声に入る）。[[post-review-product-direction-2026-10-28]] の Open Questions「新規性スコアの定義」には、説明しやすい「同じ投稿を除いて k 番目に近い意見との近さ」で足りるという材料になる

### 一緒に言われた話題（つながり線）

同じ投稿の中で一緒に書かれた下位クラスタの組を、偶然では説明できないものだけ、広聴AI の散布図の上で線で結ぶ。線を押すと、両方を書いた投稿の意見を左右に並べる。[[graph-visualization-proposal-2026-05-25]] の「クラスタ内 MST ＋クラスタ間の橋」の橋を、LLM ではなく実データの共起で引く版（地図は作り直さず線を重ねる。同ページの移植経路 A）。

- このデータは 1 本の PR を課題ごとの comment に割っているので、PR で束ねた（8,909 本の 41% が 2 つ以上の上位クラスタにまたがる。comment_id で束ねると 18,802 件中 1,005 件だけ）
- 偶然の見込みは、含む話題の数が同じ投稿どうしで出して足す（層別）。単純な n_x·n_y/N は話題が 1 つの投稿も組を作れるものとして数え、見込みの合計が実際の 1.16 倍になる（comment_id で束ねると 6.6 倍）。ポアソン検定で、Bonferroni 1% の厳しい段は 127 組、Benjamini–Hochberg 5% の緩い段は 456 組
- 線のほとんどは、隣り合う下位クラスタ（同じ話題を割ったもの）を結ぶ短い線。地図の対角線の 10% 以上離れた組は、厳しい段で 6 組。それが散布図の裂け目の候補になる
  - 性犯罪対策の強化と厳罰化（安全保障と情報管理）× 被害者支援体制の不備（世代間の負担と社会保障）：18 本・偶然の見込みの 81 倍・24%
  - 終末期医療の自己決定権（医療制度）× 安楽死と尊厳死の議論（世代間の負担と社会保障）：5 本・128 倍・31%
- 緩い段では、地図が AI の側に置いた「AI を教育に入れる話」の下位クラスタが、教育の下位クラスタと一緒に書かれている組が 8 組ある
- 弱いところ：離れた線は少ない。AI の聞き手が話題を順に尋ねたことによる共起も混ざりうる。作者がほぼ全部同じ bot なので、同じ人の複数の PR を見分けられない

### 自分の声を探す

文を入れると字面の近い意見を探し、似た声の数・どのまとまりに多いか・地図の上のおおよその位置を出す。投稿の URL や番号でも引ける。参加者向け（[[post-review-product-direction-2026-10-28]] の「自分の投稿」、farbrain の「自分の投稿のハイライト」）。入れた文はどこにも送らず、索引もブラウザの中で作る。

- 日本語は 2 文字の組と、ひらがな以外の 1 文字の TF-IDF。意見 2,000 件で比べると、近い 10 件が同じ上位のまとまりに入る割合は 0.51（埋め込みなら 0.81）
- 近さ 0.30 以上を「似た声」として数える（2 件が同じ上位のまとまりに入る割合が半分を超える境）。データに無い話題の文は、ほぼ 0.30 に届かない
- 例：「マイナンバーカードが使いにくい」は似た声 77 件、「夫婦別姓を早く導入してほしい」は 13 件（13 件とも選択的夫婦別姓の意見）
- 字面の近さなので、言い換え（「給料」と「給与」）は拾えず、賛否も区別しない。意味の近さで探すには、入れた文を埋め込みにする API が要る
- 索引の作成は日本語で約 260ms。repo の方針「重い計算は Python で事前に」とは合わないが、事前計算なしで作った（作る担当への指示による）

### merge された提案

結果の属性（ここでは PR が merge されたか）を上位のまとまりごとに数え、どのまとまりも同じ割合なら偶然で散らばる範囲（二項分布の 95%）を帯で重ねる。一般には、パブコメの「意見に対する考え方」のような、意見ごとの結果を想定している。

- `public_result.json` の中では、市民の PR（AI インタビュアー経由）は 8,820 本中 48 本が merge（0.54%）。人が直接出した PR は 79 本中 40 本
- merge されなかった市民の PR の 99% は open のまま（merge も close もされていない）。「merge されなかった」の大半は判断が記録されないまま残ったもので、「採らないと決めた」記録ではない
- 出した時期の影響が大きい（市民の PR の merge は、5 月 2.0%・6 月 1.1%・7 月 0.05%）
- 政治的に強い読まれ方をしやすいので、評価の言葉を使わず、注意書きをページの上に置いた。最初に付けた「採否の地図」という名前は、判断があったように読めるので外した（ページの題は「採られた声」）。まとまり別の内訳は個人 repo の README にあり、公開するかは nishio が決める（この wiki には載せない）

## `public_result.json` に足りない項目

どれも値は `arguments[].attributes`（自由形式）に入るので、契約を変えずに描ける。足りないのは **その属性が何か** を宣言する場所で、個人 repo の README の 1 か所にまとめた。

- 宣言したいこと：どの属性が「同じ人の同じ投稿」を束ねるか（5 つ全部が要る。このデータは comment_id が「PR の中の課題 1 件」なので、`pr_number` を引数で渡している）、どの属性が日時か、どの属性が結果で、どの値を「採られた」とみなすか、値の表示名、事前計算した値が何を測ったか
- 提案：省略可能なトップレベルキー `attribute_meta` に、属性ごとの型（id / datetime / boolean / category / number）・役割（group / outcome）・表示名を置く。賛否スライダーで出た「何への賛否か」（[[team-mirai-2025-open-dataset]] の「個人 repo のカタログ」）も、`stance_score` の `target` として同じ場所に書ける
- 日時の型だけなら、契約を変えずに、本体の公開ビューアの型の推定（kouchou-ai main `ddd0bacd` の `apps/public-viewer/components/report/attributeFilterUtils.ts` の `computeAttributeMetas`）に足す道もある。今は数値とカテゴリの 2 つだけで、`created_at` は 8,883 個の値のカテゴリになる
- 意見が 1 件も抽出されなかった入力は、契約のどこにも残らない（このデータでは意見の無い PR が 779 本）。日ごとの投稿の数や、採られた割合の分母を「意見のある投稿」でしか取れない

## 作り方

- 変換スクリプト（個人 repo の `scripts/team_mirai_to_public_result.py`）が、元データの PR の表から作成日時・merge の有無・作者の種別を、`arguments[].attributes` の `created_at` / `merged` / `author_kind` に入れるようにした。本体の入力 CSV の `attribute_*` 列と同じ扱いで、`propertyMap` には入れない。`attributes` 以外の全項目は前と同じで、ファイルは 10.0MB → 12.1MB
- 5 つは Claude Code の workflow で並列に作った。可視化ごとに作る担当 1 と、別の担当が確かめ直して直す 1、最後に README と一覧をまとめる 1 の計 11
  - 確かめる担当が直した例：日本語の変換中に検索が走る、読み込み中や失敗したときの表示、`?data=` で別のレポートを読むと例文が空振りする（題材の事情の持ち込み）、断片にあった再現しない数値
- 並列の担当に渡したサーバの止め方（`(cd … && python3 -m http.server …) & echo $!`）では、外側のシェルの PID しか残らず、python 本体が残った。`python3 -m http.server <port> --directory docs &` のように本体を直接裏に回して `$!` を取る

## Open Questions

- 一緒に言われた話題の偶然の見込みを、層別と単純のどちらにするか（厳しい段はどちらも 127 組で、うち 104 組が共通）
- merge された提案のページを公開するか。PR の `state`（open / closed）も属性に入れて、merge／閉じた／open の 3 値で描くか
- `attribute_meta` を、賛否の対象と合わせて公開契約に足す提案にするか（[[open-decisions]] の A13・A14 には、方針が動いたら書く）
