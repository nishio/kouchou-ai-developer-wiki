[Issue #1156](https://github.com/digitaldemocracy2030/kouchou-ai/issues/1156) は、意見が複数の元回答を参照できることと、いつ同じ意見や回答を束ねるかを扱う。先に仕様をLeanで小さく定義し、その実行結果をPython・TSそれぞれの差分テストの基準にする案が合っている。

2026-11-25に、Issue本文・コメント（0件）、関連open PR、および本体main `afde1cb9`、org版main `7a9c921` を確認した。Issue本文は起票時の旧serverlessの挙動を記述している。現在のorg版は [PR #2](https://github.com/digitaldemocracy2030/kouchou-ai-serverless/pull/2) 以降、本体と同じく、同一回答内で同文の意見をまとめ、別回答の同文は別に保持する。両方の公開JSONの `arguments[].comment_id` は単一値。新しい多対多は現状の再現ではなく設計変更になる。[[source-code]]、[[serverless-remaining-divergences-2026-11-24]]より。

## 仕様として先に決めること

最初に回答と意見の出典を、文字列IDで表した有限の辺の集合 `(opinion_id, comment_id)` とする。束ねるかどうかは別の規則にする。複数回答の同じ意見を表示で1つに束ねても、別回答である事実や元の属性、意見ごとのスコアを失わないようにする。

| 決めるもの | 仕様案と境界例 |
|---|---|
| 出典の辺とID | 辺の重複は同じ対応として扱う。参照先不明の辺をどう扱うか決める。IDは文字列として扱い、`"001"` と `"1"`、`"9007199254740992"` と `"9007199254740993"` を区別する |
| 束ね方 | 完全一致など、合意した同一性の規則を独立に定義する。最初のモデルでは同値であるかを決めるキーを入力として与えられるようにする。意味類似度やクラスタリングの挙動はその外に置く |
| 件数と属性 | 入力回答数、抽出された意見の出現数、束ねた意見の数を区別する。クラスタ内のユニークな回答数を出すなら、子の件数の和でなく出典IDの和集合で数える。複数回答の属性を最初に現れた値へ潰さない |
| 公開と互換 | 原文公開OFFでも原文のない古いJSONを読める。公開する本文と、出典関係・出典リンク・件数をどこまで公開するかを別々に決める。旧単一 `comment_id` と複数参照を併存させるなら、矛盾時の扱いと代表IDの選び方を明記する |

反例に使える小さい入力。回答 A と B は本文が同じだが、ID・属性が違う。A から意見 X と Y、B から X が出たとき、辺は `{(X,A),(Y,A),(X,B)}`、入力回答は2件、意見の出現は3件、束ねた意見は2群。X と Y を同じクラスタに置いたとき、クラスタが参照するユニークな回答は2件。元コメント本文を非公開にしても、出典が存在しなかったことにはならない。

## 差分テストの組み方

1. Leanで出典の辺、決定的な束ね規則、件数、公開変換を表し、「束ねても元の出典を追える」「同じ辺を二重に記録しても対応数は増えない」「公開OFFでは本文が出ない」など合意済みの性質を証明する。既存の [#1239](https://github.com/digitaldemocracy2030/kouchou-ai/pull/1239) のようにJSONを受け取り結果を返す実行器にできる。同PRは観測時点で未mergeで、対象は依存解決・再実行・クラスタの木。
2. 同じ生成入力をLean、実際のPythonの関係・公開JSON処理、実際のTSの読込・集計・書出しに通す。辺の集合、合意した件数、公開項目、旧形式の読込結果を、**各実装からLeanへ**照合する。表示順や生成IDの表記などを比較する場合は、契約上必要かを先に確認する。
3. IDの型などの約束は生JSONで確認してから、順序の違いを取り除く。比較前にすべてを文字列へ変えるとID型の不具合を隠してしまう。欠落した辺、重複加算、公開OFFの本文混入を変異させ、テストが検出することも確かめる。[[serverless-shared-contract-mutations-2026-11-24]]より。

最初の成果物は、上の小さい例と、公開ON/OFF・旧形式の各ケースを含む仕様案とLeanの最小モデル。LLMの抽出結果や文言を実装間で比較する必要はない。Leanはモデルの性質を証明し、差分テストは実コードとモデルの対応を生成例で確認する。
