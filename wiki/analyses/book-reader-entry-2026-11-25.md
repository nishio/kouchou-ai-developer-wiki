## 問い

書籍『政治・自治体・企業に広がるブロードリスニング』（[[broad-listening-book]]）を読んで広聴AIを試そうとした人は、検索で `digitaldemocracy2030/kouchou-ai` に着き、そこで迷子になりやすい。読者向けの入口を書籍Web版に置くか、本体のドキュメントに置くか。

## 2026-11-25 時点で確認したこと

- **書籍の本文に、ツールへのリンクがない。** 書籍の repo（`digitaldemocracy2030/broad-listening-book`、wip を除く）には、広聴AIのリポジトリ・ドキュメント・ブラウザ版へのリンクが一つもなかった。10章は「オープンソースです」、13章は「ミニ広聴AIを作る」ハンズオンで終わる。読者は検索に頼ることになる。
- **README は冒頭から Docker の前提条件が続く。** 「前提条件」に Docker と OpenAI の API キーが並び、ブラウザだけで試せる道は README になかった。
- **docs ではブラウザ版の扱いが小さかった。** トップの「レポートを作るには」は、セルフホストか、建ててくれる人に相談するかの二つだけだった。ブラウザ版は「始め方の選び方」と「導入を検討する方へ」に、別プロジェクトとして出てくるだけだった。
- **ブラウザ版は、初めての人を受け止める準備ができていた。** 同日の [ブラウザ版 PR #13](https://github.com/digitaldemocracy2030/kouchou-ai-serverless/pull/13) で、設定なしでサンプルを見る入口と、自分のCSVを分析する入口が分かれた。AIの選び方の案内も入った（[[serverless-onboarding-2026-11-25]]）。元コメント本文の公開も、既定で OFF になっている。
- **書籍Web版は「先行公開ドラフト」だった。** `broadlisteningbook.com/ja/` の目次は誰でも読めるが、各章はログインが必要だった。サイトのソースと問題の報告先は `lukec/broad-listening-book-site` にある。

## 判断：入口の中身は本体 docs に置き、書籍と README からはリンクだけ

入口の中身は、本体ドキュメントの「書籍を読んだ方へ」（`https://digitaldemocracy2030.github.io/kouchou-ai/book`）に置いた。書籍Web版と README からは、そこへリンクするだけにする。理由は三つある。

1. **古くなる速さが違う。** 書籍Web版は書籍の担当者が管理し、本と同じ速さでしか変わらない。ツールの入口は数日で URL が変わることがある。実際、ブラウザ版の案内先は 11-24 の org への fork で変わった。
2. **docs には、古くならない仕組みがある。** 外から張ってもらう安定した URL は docs のページが持つ、という方針になっている。リンク切れを検査する CI と、ページを移したときの旧 URL の転送もある（[[kouchou-ai-docs-overhaul-2026-10]]）。
3. **読者が実際に着くのは GitHub。** 紙の本の読者は検索から来るので、書籍Web版にだけ案内を置いても届かない。README の冒頭に 1 行置くのが、費用に対して最も効く。

ページは四段の順にした。

1. できあがったレポートを見る：ブラウザ版のサンプルと、書籍付録の公開事例
2. ブラウザ版で自分のCSVを試す：AIの選び方と、データの送り先
3. サーバ版で本格的に使う
4. 13章の続きを CLI や Python で試す

書籍Web版の各章はログインが必要なので、docs から章への直リンクは張らず、章の名前だけを書いた。

## ブラウザ版の位置づけ

nishio の判断で、ブラウザ版を次のように位置づけた。

> サーバ版（本体）は機能がすべてそろった版。ブラウザ版は同じ機能や同じ結果を保証しない別の実装だが、手軽なので最初に試すにはおすすめ。

「本流はどちらか」（[#921](https://github.com/digitaldemocracy2030/kouchou-ai/issues/921)）には踏み込まず、「最初に試す場所」として勧めるだけにした。README・docs トップ・「始め方の選び方」・「導入を検討する方へ」の書き方も、この位置づけに揃えた。

ブラウザ版の案内先は dd2030 の org 版に統一した。tokoroten さんが `tokoroten/kouchou-ai-serverless` で作り始めた経緯は、ブラウザ版の README の系譜に書き残し、元の repo にリンクした（nishio の方針）。

## 結果

- 本体の [PR #1265](https://github.com/digitaldemocracy2030/kouchou-ai/pull/1265)：2026-11-25 に main へ入った（`d857fd53`）。docs のデプロイ後に `/book` の公開を確認した。
- ブラウザ版の [PR #15](https://github.com/digitaldemocracy2030/kouchou-ai-serverless/pull/15)：2026-11-25 に main へ入った（`24b84b70`）。README の「使ってみる」、画面右上の GitHub リンク、書き出した HTML のフッターを org 版にした。デプロイ後の公開画面でリンク先を確認した。

## Open Questions

- 書籍Web版から `/book` へのリンクは、書籍サイト側へのお願いが必要で、まだしていない。紙の版に URL を入れられるかどうかも確認していない。
- README.en.md / README.ko.md には案内を入れていない。案内ページが日本語だけだからで、英語版の書籍の読者向けの入口はまだない。
- 書籍の読者が実際に `/book` から結果の図までたどり着けるかは、人による初回操作で確かめていない。
