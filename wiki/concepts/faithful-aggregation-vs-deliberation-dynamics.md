# 忠実な集約 と 熟議の演出 — broadlistening 系ツールの2つの重心

[[broadlistening]] 的なツールを比べるとき、「どちらが優れているか」で測ると噛み合わないことがある。多くの場合、**最適化している対象（重心）が違う**。ここでは [[kouchou-ai]] と [[ojpp|OJPP]] BroadListening を例に、2つの設計スタンスとして棲み分けるレンズを置く。[[broadlistening]] の「散布図 vs Long Context」とは別軸で、両軸は直交する。

## 2つの重心

- **忠実な集約 (faithful aggregation)** — 集まった意見の**分布をできるだけ歪めずに**地図化することを最適化する。答えたい問いは「**いま、どんな意見が、どれくらいあるか**」。合意形成や収束の判断は人間に委ねる。
- **熟議の演出 / dynamics (deliberation dynamics)** — 意見を**時間発展する系**として扱い、議論の構造・収束フェーズ・論点の穴を前に出すことを最適化する。答えたい問いは「**議論はどう動いていて、何が足りないか**」。体感・ナラティブ性が価値。

kouchou-ai は前者に、OJPP BroadListening は後者に重心がある。両者は同じ入力（市民の意見）に対して**別の問い**に答える道具だと見ると整理しやすい。

## それぞれが最適化しているもの

### 忠実な集約 — kouchou-ai
実埋め込み → UMAP → 階層クラスタリング（KMeans + Ward 階層マージ）→ LLM ラベリング。ここでの品質は「人間分布の忠実さ」と「ラベルが探索の手がかりとして機能するか」で測られる。地図は静的なスナップショットで、「どう読み、どう決めるか」は人間側に残す。[[broadlistening]] の「遊園地の地図」比喩がそのまま設計目標になっている。

### 熟議の演出 — OJPP BroadListening
LLM による **argument mining**（主張・前提・根拠・反論と、支持/攻撃の関係）で議論構造を取り出し、デジタルフェロモン（stigmergy）・適応度・quorum sensing で意見の盛衰と収束フェーズ（OPEN→DELIBERATION→CONVERGENCE→CLOSED）を時間発展として見せる。生物学メタファのストーリーテリングが前面に出る。[[ojpp-repo-source-2026-10-13]]より。

## なぜ「棲み分け」なのか

同じ画面に両方を無理に同居させると、互いの前提がぶつかる。

- 忠実な集約のレイヤーに演出側の仕組み（AI が意見を生成して注入する、quorum で自動的に「収束・終了」を宣言する）を混ぜると、「地図が実在の人間分布を表している」という**信頼**が崩れうる。少数意見を見えやすくする目的とも相性が悪い。
- 逆に、熟議の演出ツールに集約側の忠実さ指標を当てて「埋め込みが粗い」「可視化座標に意味がない」と言うのは、**そのツールが狙っていない指標**で採点していることになる。

だから「1 本のパイプラインに全部入れる」より、**レイヤー（または別ビュー / plugin）として分ける**のが素直。kouchou-ai 自身も `analysis_mode=llm_grouping` で散布図系と Long Context 系を mode として分けており（[[broadlistening]]）、重心の違うものを並立させる発想は既にある。

## OJPP から参考になる点（熟議の演出側の道具）

集約の忠実さを壊さずに、別レイヤーとして取り込める着想がある。

1. **構造化抽出（argument mining）** — kouchou-ai の意見単位は flat なので、主張・根拠・反論といった議論構造を持たせると「熟議の質」を見る用途に効く。取り込むなら confidence は固定値でなく実測（自己評価や複数サンプル一致度）にしたい。
2. **gap detection（語られていない論点・弱い前提の指摘）** — 「地図にまだ無いゾーン」を示し、追加収集の設計（[[idobata]] のような深掘り収集）へ回す入口になりうる。
3. **時間発展スナップショット** — 同じテーマの再分析を時系列で比較する視点。kouchou-ai は基本が単発スナップショットなので、「意見分布の時間変化」を見たい場面で補完になる。

## kouchou-ai への含意

- 重心は「忠実な集約」に置いたまま、上記 1–3 を**集約レイヤーと分離した別ビュー / 実験 plugin** として検討する（[[nishio]] の CLI-first 方針とも整合）。
- 一方で「集約レイヤーに演出を混ぜる」設計（AI 合成意見の意見プールへの注入、quorum による自動収束・自動 CLOSE）は、忠実な集約の価値と逆行するため避ける。詳しい技術的根拠と各実装の読み解きは [[ojpp-vs-kouchou-ai-broadlistening-model-2026-10-13]]・[[ojpp-agent-first-design-read-2026-10-13]]。
